# 환경 사실 카드 (외부 의존물 생존표)

> **⚠️ 아래 표는 예시다(2026-08 기준). 첫 세션에서 본인이 실제로 쓰는 것으로 교체하고, 이 문장을 지워라.**

## 왜 이 파일이 있나

취업 캠페인은 남의 서비스 위에서 굴러간다. 코테 훈련 플랫폼, 회사 채용 사이트, 공고 감시용 API, 설치한 스킬. **이것들은 예고 없이 사라지고, 사라진 줄 모른 채 세운 계획은 통째로 무효가 된다.**

문제는 이 사실들이 여러 문서에 **전제로만 흩어져** 박힌다는 것이다. "A 플랫폼에서 훈련한다"가 로드맵에도, 치트시트에도, 주간 계획에도 흩어져 있으면, A가 종료됐을 때 어느 문서를 고쳐야 하는지 아무도 모른다. 그리고 LLM은 세션마다 기억이 리셋되므로 **낡은 문장을 읽고 그것을 현재로 믿는다.**

이 표는 그 흩어짐을 막는 단일 정본이다. 템플릿 원작자는 이 파일이 없던 시절 **같은 계열 사고를 두 번** 겪었다(의존하던 코테 플랫폼 두 곳이 차례로 종료됐는데 둘 다 뒤늦게 발견). 두 번째 사고 때 만들어진 것이 이 파일이다.

## 운용 (3단계)

1. **계획·권고에 아래 이름을 올리기 전 이 표를 본다.** "○○에서 연습하자", "△△ API로 감시하자"는 말이 나오는 순간이 조회 시점이다.
2. **상태가 바뀌면 이 표를 먼저 고치고, 곧바로 `Grep`으로 레포 전체 역참조 스윕**을 돌려 그 이름이 등장하는 다른 문장들을 함께 고친다. 한 곳만 고치면 낡은 문장이 정본 행세를 한다. 폐기된 항목은 **지우지 말고** 취소선 + 종료 시점 + 대체 수단으로 남긴다(다시 후보로 떠오르는 것을 막는 게 목적).
3. **분기 1회, 🟢 항목의 생존만 재확인한다.** 표가 짧으므로 10분이면 끝난다. 다음 확인 예정일을 아래에 적어둘 것.

> **이 파일 자체도 낡는다.** 최종 확인일이 6개월 이상 지난 행은 신뢰하지 말고 다시 확인하라. 날짜 없는 행은 없어야 한다.

**다음 전수 확인 예정일: `____년 __월`**

|---|---|---|---|
| (예) 프로그래머스 | 🟢 운영 | 2026-08 | 훈련 + 다수 기업 실전 플랫폼 |
| (예) 백준(acmicpc.net) | 🔴 2026-04-28 종료 | 2026-08 | 16년 운영 후 폐쇄. "백준 골드급"처럼 **난이도 척도로 쓰는 표현은 계속 유효** — 그 용법까지 지우지 말 것 |

## 채용 공고 감시 채널

| 대상 | 채널(URL·API) | 상태 | 최종 확인 |
|---|---|---|---|
| (예) A사 | 채용 플랫폼 공개 API | 🟢 정본 검증됨 | |
| (예) B사 | 공식 채용 사이트 | 🟡 봇 차단(403) → 우회 경로 사용 | |
| (예) C사 | ~~구형 API~~ | 🔴 **오측정 폐기** — 다른 사이트의 백엔드였음 | |

> 감시 채널은 "호출이 되고 그럴듯한 데이터가 온다"가 "그 사이트의 정본이다"를 보장하지 않는다. 프론트가 실제로 호출하는 백엔드인지 검증한 뒤 등재하고, 검증 방법도 함께 적어라.
