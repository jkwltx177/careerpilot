# 산출물/ — 구조와 로컬 저지

> 자소서·이력서·코테 자산이 쌓이는 작업 폴더. 지원서 = **회사별**, 코테 = **기능별**로 관리한다.

```
산출물/
├── 지원서/<회사>/          # 회사별 지원 서류 — 하위 3분류 고정 (폴더 예시 = 지원서/_example, 복사 후 삭제)
│   ├── 제출물/            #   자소서·이력서 버전들 · 제출본 · 입력값 (실제로 내는/낸 것)
│   ├── 검증/              #   제출 전 검증·검수·팩트체크 문서 (제출물을 지키는 것)
│   └── 자료/              #   설명회·공식 채용 사이트·커뮤니티 등 수집 자료 (근거가 되는 것)
├── 코테/
│   ├── 전략/             #   전략 로드맵·약점 플랜
│   ├── 문제/             #   ★로컬 저지 문제들 — 폴더당 문제.md·solution.py·testcases.json
│   ├── 복기/             #   실전·훈련 복기 기록
│   ├── 치트시트/          #   템플릿·체크리스트
│   └── judge.py          #   공용 채점기
└── 캠페인/
    └── 관제탑.md         # ★데일리 단일 실행 뷰 — 전 트랙 보드·주간 표·D-day (+ 시즌 로드맵·기업 캘린더)
```

## 로컬 저지 (프로그래머스식 제출·채점)

```bash
cd 산출물/코테
python judge.py 문제/_example            # 코드 실행 (예제만)
python judge.py 문제/_example --submit   # 제출 (전체 채점 + 점수)
```

- 문제 폴더의 `solution.py`에 풀이를 작성 → 제출하면 케이스별 통과/실패·실행 시간·총점이 나온다.
- 케이스별 시간 제한(별도 프로세스)으로 **효율성 채점**까지 실전과 같은 감각.
- 새 문제 추가법은 `문제/_example/문제.md` 하단 참조 — 실전에서 만난 문제를 Claude에게 재구성시키고 "채점 케이스를 브루트포스 대조로 만들어줘"라고 하면 검증된 정답 데이터가 생성된다(템플릿 원작자의 훈련 방식).
- 훈련 원칙: `testcases.json`의 grading 케이스는 열어보지 않는다.

### ⚠️ 언제 쓰고, 언제 쓰지 않나 (제작 낭비 방지)

**로컬 저지는 "공개 플랫폼에 없는 문제" 전용이다.** 쓰는 경우는 둘뿐:

1. **실전 복기 재구성판** — 응시했던 회사 코테 문제처럼 세상 어디에도 없는 문제. 이게 로컬 저지의 원래 존재 이유다.
2. **공개 플랫폼에 마땅한 문제가 없는 유형·형식** — 해당 플랫폼이 다루지 않는 알고리즘 유형이나, 표준입력(stdin) 파싱 리허설처럼 형식 자체를 훈련해야 할 때.

**그 외에는 공개 플랫폼에서 푼다.** 공개 플랫폼이 이기는 것들: ①히든 테스트케이스가 수많은 응시자에게 두들겨 맞아 정제돼 있다(자작 케이스는 "내가 정한 규칙 안에서의 정합성"일 뿐이다) ②실전 UI 리허설이 된다 ③채점 결과 캡처가 복기·면접 자산이 된다 ④제작 시간과 출제 오류 리스크가 0이다.

> 이 원칙이 없으면 "이번 주 유형 4개"를 전부 로컬 저지로 만드는 낭비가 실제로 발생한다(원작자 사례). 다만 **의존하던 공개 플랫폼이 종료되면 1·2의 범위가 넓어진다** — 그래서 플랫폼 생존 상태를 `memory/environment-facts.md`에서 먼저 확인해야 한다.

### 대용량 생성물 주의

`testcases.json`은 **생성물**이라 문제 하나가 수 MB~십수 MB까지 간다. 대형 케이스를 쓸 거라면 json을 커밋하는 대신 **시드를 고정한 생성 스크립트만 커밋하고 json은 `.gitignore`** 하는 편이 낫다(어느 PC에서든 재생성 가능). 이미 커밋한 뒤에는 히스토리에서 지우기 어려우니 처음에 정할 것.

## 관제탑 (캠페인/관제탑.md)

트랙이 3개를 넘으면 정보가 흩어진다. 관제탑은 전 트랙·주간 계획·D-day를 한 화면에 모은 **데일리 단일 진입점** — Claude가 세션마다 갱신하고, 사용자는 매일 이 파일 하나만 읽는다. 상세·히스토리는 여기 쌓지 않고 정본(status·로드맵·연대기)으로 링크만. 운용 규칙은 관제탑.md 하단 참조.
